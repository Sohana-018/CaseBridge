# CaseBridge Deployment Guide (Phase 18)

This guide documents the production deployment architecture and configuration for CaseBridge.

---

## 1. Architecture Overview

- **Backend**: FastAPI web service hosted on [Render](https://render.com) (or equivalent Linux container platform).
- **Frontend**: Single-Page Application (React + Vite + Tailwind CSS) deployed on [Vercel](https://vercel.com) (or static web host).
- **Database**: SQLite embedded database file (`casebridge.db`) with automated seed/initialization scripts, or persistent disk volume.

---

## 2. Backend Deployment (Render)

The backend service is declared in [`render.yaml`](../render.yaml) as a Blueprint:

- **Root Directory**: `backend`
- **Build Command**: `pip install -r requirements.txt`
- **Start Command**: `python ../scripts/import_csv.py && uvicorn app.main:app --host 0.0.0.0 --port $PORT`

### 2.1 Cold-Start Behaviour & Automated Database Seeding

Render's free tier spins down instances after 15 minutes of inactivity. When a new incoming HTTP request arrives:

1. **Container Initialization**: Render spins up the container and executes `startCommand`.
2. **Automated Seeding (`import_csv.py`)**:
   - Runs `python ../scripts/import_csv.py` before the web server begins accepting traffic.
   - Idempotently creates tables and inserts initial operational records (25 institutions, 555 cases, chronological events) from `data/seed/` if the database is unseeded or restarted in a fresh ephemeral container.
   - Resets sequence counters above the highest imported case numbers and executes initial alert rule evaluations.
   - If tables and records already exist, the script completes in milliseconds without duplicating records (`0 created, 555 skipped`).
3. **Server Launch**: Once seeding completes, `uvicorn` binds to `0.0.0.0:$PORT` and starts listening for API traffic.
4. **Latency Profile**:
   - **Cold-Start Request**: Expect an initial latency of ~30–50 seconds on Render free tier during cold container spin-up and Python initialization.
   - **Warm Requests**: Handled in under 50ms with zero subsequent startup overhead while the instance remains active.

### 2.2 Core Environment Variables

| Variable | Required | Default | Description |
|---|---|---|---|
| `ENV` | Yes | `prod` | Runtime environment. When set to `prod`, startup will abort immediately if `JWT_SECRET` is unset. |
| `JWT_SECRET` | Yes | *None* | Secure random string (64+ hex characters). Auto-generated by Render Blueprint (`generateValue: true`). Never commit secrets to source control. |
| `CORS_ORIGINS` | Yes | *None* | Comma-separated list of allowed frontend origins (e.g. `https://casebridge.vercel.app,https://yourdomain.com`). |
| `ALLOW_DEMO_LOGIN` | No | `false` | Disables mock-login and credential auto-fill in production. Set to `true` only in staging/demo environments. |
| `AUTO_SEED` | No | `false` | When set to `true` and the cases table is empty, automatically loads `data/seed` on startup using idempotent import logic, alert refresh, and an overlap scan. Note: `ALLOW_DEMO_LOGIN=true` is needed for the one-click demo accounts. |
| `DEMO_ADMIN_PASSWORD` | No | `admin123` | Password override for the demo administrator account. |
| `DEMO_COORDINATOR_PASSWORD` | No | `coord123` | Password override for the demo coordinator account. |
| `DEMO_OFFICER_PASSWORD` | No | `officer123` | Password override for the demo bureau officer accounts. |
| `DEMO_MANAGEMENT_PASSWORD` | No | `mgmt123` | Password override for the demo senior management account. |

### 2.3 Email Notification Environment Variables (SMTP)

CaseBridge uses standard SMTP with asynchronous, non-blocking background workers (`BackgroundTasks`) to send:
1. **Complaint registration confirmations** (containing the citizen's official tracking ID and tracking link).
2. **Status progression updates** (containing previous status, new status badge, administrative remarks, and tracking link).

Delivery failures fail soft (logged to stderr, does not disrupt complaint submission or case actions). Outbound emails are disabled if `SMTP_HOST` is omitted or empty.

| Variable | Required | Default | Description |
|---|---|---|---|
| `SMTP_HOST` | Yes (to enable) | *None* (disabled) | SMTP relay host (e.g. `smtp.sendgrid.net`, `smtp.mailgun.org`, `smtp.resend.com`, `smtp.gmail.com`). Leave empty to disable emails. |
| `SMTP_PORT` | No | `587` | SMTP port (`587` for STARTTLS, `465` for SSL, `25`/`2525`). |
| `SMTP_USERNAME` | Conditional | *None* | Authentication username or API key (e.g. `apikey` for SendGrid). |
| `SMTP_PASSWORD` | Conditional | *None* | Authentication password or API key secret. |
| `SMTP_FROM_EMAIL` | Yes (to enable) | *None* | Sender email address (e.g. `grievances@casebridge.gov.in` or verified domain sender). |
| `SMTP_FROM_NAME` | No | `CaseBridge Portal` | Friendly display name shown to complainants. |
| `SMTP_TLS` | No | `true` | Enable STARTTLS command encryption (`true`/`false`). |
| `SMTP_SSL` | No | `false` | Enable direct SSL socket encryption (`true`/`false`, typically port 465). |
| `SMTP_TIMEOUT` | No | `10` | Socket timeout in seconds. |
| `FRONTEND_URL` | Yes (to enable) | `http://localhost:5173` | Public URL of the frontend application (e.g. `https://casebridge.vercel.app`) used to build deep links (`{FRONTEND_URL}/cases/{case_no}`) in email messages. |

## 3. Frontend Deployment (Vercel)

The frontend SPA routing configuration is defined in [`frontend/vercel.json`](../frontend/vercel.json), redirecting all client routes to `/index.html`:

```json
{
  "rewrites": [
    {
      "source": "/(.*)",
      "destination": "/index.html"
    }
  ]
}
```

### Environment Variables

| Variable | Required | Description |
|---|---|---|
| `VITE_API_URL` | Yes | Absolute root URL of the deployed backend API (e.g. `https://casebridge-backend.onrender.com`). Do not include trailing slashes. |

Build settings in Vercel:
- **Framework Preset**: Vite
- **Root Directory**: `frontend`
- **Build Command**: `npm run build`
- **Output Directory**: `dist`
