# Overlap Detection — Evaluation (Phase 12)

**All data in this project is synthetic demo data. No real AICTE records are used.**

This is the rebuilt, **non-circular** evaluation. The previous ground truth was
generated by applying the same category/status rules that the engine uses, so
labels could be predicted from metadata alone and descriptions were never
tested. That dataset is replaced.

## 1. How the ground truth is built

`scripts/generate_issue_dataset.py` (deterministic seed `20261024`):

1. It invents **hidden `issue_id` values** — a complaint that actually exists.
   They live only in `data/eval/hidden_issues.csv`; the `cases` table and the
   API have no `issue_id` field.
2. Every multi-case issue is expressed as 2–3 cases in **different Bureaus**,
   with **paraphrased descriptions** of the same underlying problem.
3. Hard cases are deliberate:
   - **same category, different issue** → `not_related`
   - **different category, same issue** → `related` (the alternate category is
     chosen from outside the engine's related-category map, so metadata cannot
     solve it)
   - some issue cases use a **deliberately low-overlap paraphrase** (same issue,
     almost no shared wording).
4. `label` is computed **only** by comparing `issue_id`:
   `related` ⇔ the two cases share an `issue_id`. Category, status, Bureau and
   text similarity are never used to assign labels.

corpus. Same-Bureau pairs are excluded because a cross-Bureau overlap is the
thing being detected.

## 2. Protocol

- The engine is evaluated **as-is**: `backend/app/services/overlap.py` was not
  changed, and its default thresholds (`sim_high=0.50`, `sim_medium=0.50`) were
  used without tuning.
- Deterministic 50/50 split, stratified by label, so both halves contain
  positives: **493 development / 493 test**.
- Positive prediction = band **Medium or above**.
- Baseline = "flag every same-institution, different-Bureau pair".
- Raw counts are reported alongside ratios.

## 3. Results (current engine, unchanged)

## 4. Where the errors come from

**False positives: 439**

| Cause | Count |
|---|---|
| Same category, **different issue** (metadata-only match) | **250** |
| Different category, **text similarity only** | **189** |

**False negatives: 13**

| Cause | Count |
|---|---|
| Excluded by candidate rules (disposed / same Bureau / >365 days) | 0 |
| Candidate, but scored Low (paraphrase too distant) | 13 |

Examples:

- FP: `OC-2026-00007` (sports-quota admission issue) vs `RO-2026-00011`
  (ragging issue), different categories, flagged on `text_similarity 0.67`
  because both descriptions use the same generic sentence frame.
- FN: two cases sharing `ISS-0047` but filed under `fee_refund` and
  `examination`; one uses a low-overlap paraphrase, similarity 0.39, band Low.

## 5. Honest interpretation

- The rebuilt labels expose the circularity: on independent labels the engine
  is far from the old "perfect" score. **250 of 439 false positives come from
  the same-category rule alone**, i.e. metadata that used to *be* the label.
- The text signal is not strong enough either: the rapidfuzz token-set
  component has a high floor on short, formulaic sentences, producing 189
  text-only false positives at similarity 0.50–0.67 between unrelated issues.
- Paraphrasing matters in the other direction: 13 genuinely related pairs are
  scored Low when the wording barely overlaps, so recall is 0.928, not 1.000.
- With precision 0.276, the current engine still beats the baseline on
  precision (+0.093) but is not yet good enough to present as a reliable
  detector. This is the measurement to improve next.
- The corpus is synthetic and rule-free at labelling time, but it is still one
  generator with one seed; results should be re-checked on a second seed and on
  real (or independently authored) data before any production claim.

## 6. Reproduce

From the repository root:

```bash
python scripts/generate_issue_dataset.py   # builds casebridge_eval.db + labels
python scripts/evaluate_overlap.py         # reports counts on dev/test
```

The engine is intentionally unchanged for this measurement. Any future change
to `services/overlap.py` must be judged against this held-out test split.
